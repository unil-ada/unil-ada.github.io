Advanced Data Analytics · The semester project

The semester project

One project, carried out individually — the whole assessment for this course.

What it is

The work
One project, carried out individually You choose a question, find data, apply methods from the course, and write it up. The project is the whole assessment for this course.
What you hand in
One GitHub repository It holds the paper, the data, the code, and a 15-minute recording. The paper is about ten pages in the SIAM conference style, with eight required sections. Submission is the repository — not an email attachment and not Moodle.
How you submit
One email with the repository link and the commit identifier The commit you name is the one that is graded, so nothing you push afterwards changes it — and nothing is lost if you keep working. The guidelines show the one command that prints it.
Your GitHub account
Must show your full name Set your real name in your GitHub profile before you submit. A submission from an account that cannot be matched to a registered student is not graded, and we will not guess whose it is.
Two dates
A 200-word proposal, then the project Email the proposal to the teaching assistant; the reply approving it is the sign-off, and work starts after that. Dates are confirmed at the start of the semester and announced here and on Moodle at the same time.
AI tools
Allowed, and expected — but declared Use assistants for code and prose. List every tool you used, and what you used it for, in the appendix. Undeclared use is misconduct; declared use is normal practice.
Compute
Your Nuvolos workspace — and that is what is provided It is enough for the methods this course teaches. Scope the project to fit it, at proposal stage. You may use your own compute at your own cost, but it earns no marks: the work is assessed, not the hardware.
How the repository looks
Split by stage — not one enormous notebook One notebook per stage: get the data, clean it, model it, make the figures. Each runs top to bottom from a fresh kernel. A single file holding the whole analysis cannot be checked, and cannot show which parts are yours.
Code you did not write
Attribute it, and it costs you nothing Libraries need no attribution. Anything else you did not write — a function from a forum, a chunk of a repository, code from an assistant — is named where it appears and listed in the appendix. Declared reuse is assessed on what you built with it; undeclared reuse is misconduct, whatever its size.
If the result is negative
An honest null result can score full marks A hypothesis that data does not support is a real finding, and a well-told account of why it failed is worth more than a result that was helped along.

The two documents

Requirements
Requirements for the semester project (PDF) The binding text: deadlines, what is submitted, how it is assessed. Where this page and the requirements differ, the requirements are what counts.
Shipping guidelines
Shipping your project (PDF) Practical advice, and not binding: folder layout, the README, reproducibility, the recording, and the one test to run before you submit.

Gallery

Selected projects are published here, with their authors' permission and credited to them. Consent is asked for at submission, is entirely optional, and has no bearing on the grade.

The gallery opens with the first consenting projects from this cohort. Until then, the requirements above describe the standard the work is held to.
